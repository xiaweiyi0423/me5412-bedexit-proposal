### 2. 【严重度：高】单侧悬臂滑块的受力计算漏掉了“座板前后偏载（俯仰力矩）”，且力合成方式不符合导轨样本规范

- **在哪里：**
  - Slide 8 讲稿指南、Slide 10（驱动选型）、网页第 5、6 节。
  - 代码文件 `model/calc_v13/seat_1dof_slider.py`（第 83–95 行）和 `seat_1dof_v5_checks.py`（`forces()` 函数，第 95–105 行）。
- **原文与代码证据：**
  - Slide 10：“双导轨、每轨两个滑块：偏载悬臂 659 N·m，每个滑块约 3.1 kN”。
  - 在 `seat_1dof_slider.py` 第 92 行算平面内受力时，代码写的是：
    ```python
    # choose fl so the carriage moment is zero if possible (link takes the rotation)
    fl = -m2(C - X, Fv) / m2(Y - X, uL)
    rest = -(Fv + fl * uL); fs = rest @ d_; fn = rest @ nr
    ```
    算出了导轨平面内的法向力 `fn` 最大为 **2080 N**（网页第 5 节表格：“滑块法向力 2080 N”）。
  - 但在 `seat_1dof_v5_checks.py` 的 `forces()` 里算每个滑块的受力时：
    ```python
    Mx = F * (Y["rail"] - yl); Me = Mx * abs(e[0]); Mn = Mx * abs(nf[0])
    Fr = Me / RAIL_GAP; Fc = Mn / CARR_SPAN
    ... per_carriage_lateral_N=round(Fr / 2 + Fc / 2)
    ```
- **为什么是问题：**
  - **已确认的事实 1（方向与分量搞混）：** `Fr`（2465 N）是两根导轨分担侧倾力矩产生的**垂直于侧板平面（y 方向）**的拉压力；而 `Fc`（3639 N）是同一导轨上两个滑块分担偏航力矩产生的**导轨平面内（nf 方向）**的力。这两个力互相垂直，而且 `Fc` 所在的平面内本来还有 `seat_1dof_slider.py` 算出的 2080 N 平面法向力 `fn`！`forces()` 函数既把互相垂直的 `Fr/2` 和 `Fc/2` 直接标量相加，又把平面内的 `fn = 2080 N`（分到 4 个滑块每个约 520 N）漏掉了。
  - **已确认的事实 2（铰点位置不一致导致的附加俯仰力矩）：** 在 `seat_1dof_v5_checks.py` 的 `carriages()` 函数里，4 个滑块分布中心在 `P1 + 0.075 * e`（即铰点 `c1` 往导轨上方偏移 75 mm 处），而铰点 `c1` 在滑块板下端 `P1`。平面内的力 `fn`（2080 N）和丝杠推力作用在 `P1` 上，对滑块群中心会产生约 $2080\text{ N} \times 0.075\text{ m} \approx 156\text{ N}\cdot\text{m}$ 的俯仰力矩，这会让上下滑块承受一正一负的附加法向力（约 $\pm 520\text{ N}$）。
  - **影响：** 虽然 15/20 号导轨的额定静载荷很大（>15 kN），不会因此颠覆“双导轨可行”的结论，但如果老师或助教懂机械设计、细看你们的自由体图，会立刻发现平面内法向力 2080 N 在滑块校核时凭空消失了。
- **怎么改 / 怎么确认：**
  - 在 `seat_1dof_v5_checks.py` 的 `forces()` 中，明确写出每个滑块的两个正交分量：垂直于侧板的力 $F_y = F_r / 2 \approx 1.23\text{ kN}$，导轨平面内的法向力 $F_n = F_c / 2 + F_{\text{normal, in-plane}} / 4 + \Delta F_{\text{pitch}} \approx 1.82 + 0.52 + 0.52 \approx 2.86\text{ kN}$，合力或等效载荷约 3.1–4.1 kN。这样物理逻辑完全闭合，而且最终数字（约 3–4 kN）几乎不用改。

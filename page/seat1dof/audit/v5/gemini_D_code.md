作为代码与数字核查者，我对第五版（含 5.1 分区坐垫）的计算脚本、生成的 JSON 数据、网页源码（`template.html`）以及设计总结（`seat_1dof_summary.md`）进行了逐行比对和公式复核。

整体来看，核心的线性规划（`seat_trajectory.effort` 新增的分布载荷分支）、虚功原理求丝杠推力、几何运动学（`seat_1dof_slider.py`）和抗倾翻计算本身在数学上是正确的。但是，在**坐垫物理建模、边界条件处理、逐帧求解的加速技巧，以及文档与代码的数据同步**上，存在几处明显的计算错误和漏洞。

按重要性从高到低排列如下：

---

### 1. 【严重度：高】坐下静载（`sitdown`）计算漏掉了压到底（bottoming）后的附加刚度，导致坐下峰值压强被严重低估且违反静力平衡

- **位置**：`seat_cushion_zoned.py` 的 `sitdown(c)` 函数（第 95–104 行），以及 `seat_cushion.py` 的 `sitdown(c)`（第 92–100 行）；影响网页第 7 步的坐着下陷与坐着峰值压强数据。
- **代码证据**：
  在起身阶段的 `load()` 函数（第 42–43 行）中，当压缩量 `sq > 0.8 * t`（压到底）时，压强公式有 50 倍刚度的惩罚项：
  ```python
  bott = sq > 0.8 * t
  p = k * np.minimum(sq, 0.8 * t) + np.where(bott, 50 * k * (sq - 0.8 * t), 0)
  ```
  但在 `sitdown(c)` 函数（第 100–103 行）中，循环在任一点碰到 `0.8 * t` 的瞬间就**直接终止**，且完全没有加上压到底的附加刚度：
  ```python
  F = float((k * np.minimum(sq, 0.8 * t) * ds * W).sum())
  if F >= target or (sq > 0.8 * t).any():
      p = k * np.minimum(sq, 0.8 * t)
      return dict(sink_mm=..., bottom=bool((sq > 0.8 * t).any()), p_peak_kPa=round(float(p.max()) / 1000, 1))
  ```
- **为什么是问题（确定的事实）**：
  当软的前区或较软的坐垫局部压缩达到 `0.8 * t` 时，整个坐垫承载的总力 `F` 还远没有达到目标载荷 `0.75 * BW`（在 `cushion.json` 的 `sitdown` 里可以看到，“软”坐垫停下时 `F_BW` 只有 `0.41`，“分区：后硬前软”只有 `0.49`）。但代码此时直接 `return` 退出了！
  这导致了荒谬的数值结果：在 `cushion_zoned.json` 中，“后 30 / 前 1，分界 -4 cm”坐下时的峰值压强算出来只有 **18.1 kPa**（而同款刚度在“分界 -2 cm”时是 **76.0 kPa**）。原因是分界在 -4 cm 时，前区（厚 8 cm，刚度 1 kPa/cm）在 `dz` 下移过程中先达到了 64 mm（0.8×8 cm）的压到底线，触发 `(sq > 0.8 * t).any()` 提前终止了循环；此时后区（刚度 30 kPa/cm）几乎还没怎么受压，人的一大半体重根本没被托住。
- **怎么改**：
  删除 `sitdown()` 里的 `or (sq > 0.8 * t).any()` 终止条件，直接调用 `load()` 里的完整压强公式（含 `50 * k` 的压到底刚度），一直下压到总反力 `F >= target`（0.75 BW）为止。

### 2. 【严重度：高】夹点与床体干涉检查漏算了座板前端 8 cm 厚的软坐垫，且采样步长过大

- **位置**：`seat_1dof_v5_checks.py` 的 `pinch()`（第 56–68 行）和 `check_bed()`（第 34–45 行），调用了 `seat_1dof_layout.py` 的 `seat_polys()`（第 42–47 行）。
- **代码证据**：
  `seat_polys()` 中定义座板刚性板厚度为 `PLATE_T = 0.045`（4.5 cm）：
  ```python
  plate = W([(-HALF + LIP, 0), (HALF, 0), (HALF, -PLATE_T), (-HALF + LIP, -PLATE_T)])
  ```
  而在第 7 步和第 9 步（CAD 清单）中，明确规定推荐的分区坐垫“**前区厚 8 cm，座板骨架在前区要做成下沉 3 cm 的台阶，两区顶面齐平**”。
- **为什么是问题（确定的事实）**：
  既然顶面齐平（`z = 0`）且前区坐垫厚 8 cm（或骨架下沉 3 cm），那么座板前区的下表面在局部坐标系里已经到了 **`z = -0.075 m` 到 `-0.080 m`**，比 `PLATE_T = 0.045 m` 深了 3–3.5 cm！
  然而 `pinch()` 检查“连杆—座板底面”和“座板底面—底座”，以及 `check_bed()` 检查离床间隙时，仍然只用了 4.5 cm 厚的 `plate`。连杆在座板前下方运动，座板底面往下加厚 3 cm 后，“连杆—座板底面”的实际间隙会比报告的 `15.5 cm` 小约 3 cm。
  此外，采样密度也不够：`pinch()` 用了 `sim[::4]`（每 4 帧采 1 次），`poly_pts` 步长为 5 mm；而在 `seat_1dof_slider.py` 的优化代价函数 `cost()`（第 58 行）里更是用了 `s[::10]` 和 `10 mm` 步长。
- **怎么改**：
  在 `seat_polys()` 中把前区（`x >= -0.02`）的下表面坐标改为 `-0.075`（或 `-0.080`），并将 `pinch()` 和 `check_bed()` 的遍历改为全帧 `sim`（去掉 `[::4]` 和 `[::5]`），重新核对间隙。

### 3. 【严重度：中】网页动画逐帧求解坐垫（`cushion_patch`）使用了危险的 `k0 - 4` 热启动，且二分搜索假设力随行程单调递增

- **位置**：`seat_1dof_page_data_v5.py` 的 `cushion_patch()`（第 27–38 行）和 `seat_cushion_zoned.py` 的 `solve()`（第 48–60 行）。
- **代码证据**：
  `cushion_patch()` 在求每一帧的坐垫接触时，传入了刚体接触帧号 `k0` 减去 4 作为搜索起点：
  ```python
  res, (P, A, ds) = Z.solve(sub, pz, c, max(k0 - 4.0, 0.0))
  ```
  在 `Z.solve()` 中：
  ```python
  u = max(k0, 0.0); prev = u; L = load(u, P, A, ds, c)
  while L["Fm"] < target:
      prev = u; u += 4.0
      ...
  ```
- **为什么是问题（确定的事实 + 边界隐患）**：
  1. **热启动越界问题**：对于带台阶的坐垫 `z2`（`drop = 0.02`，前区顶面比刚体座面低 2 cm），在 `u = k0 - 4` 时坐垫 당연히还没碰到大腿，要多走几厘米才碰得到，所以 `k0 - 4` 是安全的。但对于均匀坐垫 `u` 或无台阶的 `z1`，未受压的坐垫顶面就是 `SEAT.top(x)`（与刚体座面完全重合）。在 `u = k0` 时刚体座面已经接触人体，`u = k0 - 4` 只比刚体接触点退后了约 1.5 mm！如果某个姿势下接触面积很大，在 `u = k0 - 4` 时坐垫力 `L["Fm"]` 已经大于 `target`（0.5 BW），`while` 循环一次都不会执行，导致 `lo = hi = k0 - 4`，二分搜索直接失效，返回错误的过早位置。
  2. **非单调性隐患**：导轨加长 3 cm 后（`rail_ext = 0.09`），座板在行程末段会从前倾 15.8° 大幅回落并**后仰到 -3.4°**（见 `slider.json` 的 `tilt_curve`）。当座板一边上升一边往后仰（前端下沉）时，对于接触点主要在座板前端的用户，坐垫压缩量和总反力 `Fm` 在末段未必随 `u` 单调递增，粗步长（`u += 4.0`）加二分搜索可能会漏根或卡在局部。
- **怎么改**：
  `Z.solve()` 耗时极短，动画数据又是离线生成的（`seat_1dof_page_data_v5.py`），完全没有必要冒险用 `k0 - 4` 做热启动，直接从 `k0 = 0.0`（或找到第一个 `Fm > 0` 的点）开始搜即可。

### 4. 【严重度：中】`seat_cushion_zoned.py` 内部法向量重复实现，且在有 `drop` 台阶时法向力方向不对

- **位置**：`seat_cushion_zoned.py` 的 `top_z()`（第 31–33 行）和 `load()`（第 42–43 行）。
- **代码证据**：
  `top_z()` 定义了带 1 cm 斜坡过渡的坐垫顶面：
  ```python
  def top_z(x, c):
      return SEAT.top(x) - c["drop"] * np.clip((x - c["split"]) / 0.01, 0, 1)
  ```
  但在 `load()` 计算法向量时，却没有对 `top_z` 求导，而是对未降台阶的刚体表面 `SEAT.top` 求导（且没有复用 `SEAT.normal`）：
  ```python
  d = (SEAT.top(xm + 1e-4) - SEAT.top(xm - 1e-4)) / 2e-4
  nl = np.stack([-d, np.ones_like(d)], 1) / np.hypot(d, 1)[:, None]; nrm = nl @ Rm.T
  ```
- **为什么是问题（确定的事实）**：
  当 `drop = 0.03`（前区低 3 cm，过渡段长 1 cm）时，过渡斜坡的斜率高达 `-3.0`（倾角约 71°），但代码仍按平座面（法向朝上 `(0, 1)`）来算微元力方向和弧长投影 `ds`。此外，弹簧床压缩量 `sq = top_z(x, c) - z` 是沿座板局部 z 轴算的，而在座板前倾圆角处和台阶处并非沿法向压缩。虽然模型声明了是简化弹簧床，但这让 `drop > 0` 时的受力方向失真。
- **怎么改**：
  如果保留一维温克勒（Winkler）弹簧床假设（只沿座板局部 z 轴受力），则微元面积应为 `dx * W` 而不是人体弧长 `ds * W`，力方向直接取座板法向 `Rm @ [0, 1]`，这样物理上自洽且不会在斜坡处产生矛盾。

### 5. 【严重度：中】多处“中位数”统计在偶数样本下取了偏高值，且“托不住”样本在各指标中的剔除口径不一

- **位置**：
  1. `template.html` 中所有自定义 `med` 函数（第 395、570、701、732 行）：`arr[Math.floor(arr.length/2)]`。
  2. `seat_cushion_zoned.py` 的 `summarize()`（第 106–121 行）。
- **代码证据**：
  - 在 JS 中，当有效样本数 `arr.length` 为偶数时（例如 324 个总样本，或扣除 1 个 `lost` 后的 80 个单阶段样本），`arr[Math.floor(arr.length/2)]` 取的是上半区的第一个数（即第 $N/2 + 1$ 个），而不是中间两个数的平均值（Python 的 `np.median` 取的是平均）。
  - 在 `seat_cushion_zoned.py` 的 `summarize()` 中：
    - `effort_all` 和 `effort_free` 统计了全部 324 个样本（把 `lost=True` 时停在导轨末端算出的力也计入了）；
    - 但紧接着第 111 行执行了 `rs = [r for r in rs if not r.get("lost")]`，导致后面的 `pel_share`、`p_peak_kPa`、`sink_mm` **全都把 `lost` 的样本剔除了**！
- **为什么是问题（确定的事实）**：
  统计口径不一致会误导对比。一个很软的坐垫如果在 70% 阶段有很多人“托不住（lost）”，这些人原本是下陷最大、骨盆占比为 0 的最差情况；把它们从 `sink_mm` 和 `pel_share` 里剔除后，软坐垫的统计中位数反而显得更好了（幸存者偏差）。同时，网页第 7 步表格下方小字只写了“费力把‘托不住’的情况也算进去”，没提其他列（压强、骨盆占比）其实把托不住的剔除了。
- **怎么改**：
  在 `template.html` 中统一把 `med` 改为 `(a[Math.floor((a.length-1)/2)] + a[Math.floor(a.length/2)]) / 2`。在 `seat_cushion_zoned.py` 中，对于 `lost` 的情况，既然 `job_effort` 已经算出了导轨末端状态 `L = load(float(n), ...)`，就应该把该末端状态下的 `pel_share`、`p_peak_kPa`、`sink_mm` 一并填入字典参与统计，保持 324 个样本口径一致。

### 总体判断与最值得先做的一件事

- **总体判断**：第五版在运动学、静力学（虚功原理与连杆受力）和线性规划上的代码质量很高，第四版审计指出的“漏算座板偏心转动项”、“横管撞摇杆”、“前倾过大”在代码层面都已扎实修复。目前最大的漏洞集中在 **5.1 新增的坐垫代码**和**加长导轨后的数据同步**上。
- **最值得先做的一件事**：**立即修复 `seat_cushion_zoned.py`（及 `seat_cushion.py`）中的 `sitdown()` 函数**（去掉 `(sq > 0.8 * t).any()` 的提前终止，补上 `50 * k` 压到底刚度），并把 8 cm 前区坐垫的真实厚度加进 `seat_polys()` 重新跑一遍 `v5_checks.py` 和 `page_data_v5.py`。这两处改完只需几分钟重跑脚本，就能消除所有违反静力平衡的压强数字和夹点漏检。

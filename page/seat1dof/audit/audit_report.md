# 单自由度坐板 · Gemini 审计综合报告

审计对象：`page/seat_1dof.html`（第四版），以及背后的 `model/calc_v13/seat_*.py`。
- 模型：gemini-4-argon，5 个角度：A 建模与推理、B 机构与结构、C 安全与人因、D 代码与数字、E 老师与答辩。原文在 `gemini_*.md`。
- 复核：Claude 逐条回到代码和网页核对，涉及数字的都用脚本重算。另外自查了两项：夹手间隙和抗倾翻。

## 结论

运动学这条链本身经得住检查：用户集 → 设计曲线 → 四连杆 → 81 人验证。几个看上去严重的代码指控，重算后都不改变结论。

真正的问题出在**机构接进整机以后**，有三件事需要先拍板，再改机构：

1. **放手时座板大多还是前倾的。** 81 人里 64 人放手时座板前倾超过 20°，中位数 24°，只有 5 人低于 15°。此时人往回坐，座面摩擦（布料对坐垫 μ ≈ 0.4–0.5，对应 22–27°）可能拉不住，人会顺坡下滑。单自由度机构的倾角由高度决定，自锁推杆只有 10–30 mm/s，跟不上 0.3–0.5 s 的跌坐。这正是 README 第 12 版改回竖直升降的理由。
2. **扶手怎么动没有定义。** 模型里扶手随髋竖直上升；但四连杆带不动一个竖直升降的扶手。
3. **两侧连杆和立板会挡住回床时腿的转动。** README 13.1 已定“开口一侧敞开”，现在两侧都有连杆，与之冲突。

其余被核实或部分成立、但不改变结论的问题：
- **横管弯矩。** 推杆在中点推 2.8 kN、跨 0.57 m 时弯矩约 404 N·m；Ø40×4 钢管约 109 MPa，要做校核。
- **推杆需要手动应急下降。** 自锁推杆断电后会停在原位，所以要带手动应急下降。另外，最不利处推杆每走 1.3 mm 髋才升 1 mm，推杆速度要按这个比例给。
- **腿的横向宽度。** 现在按臀宽估算，没有考虑膝外展；建议立板外扩到 |y| ≥ 0.30 m 并加软垫，再用老年人测量数据核对。
- **抗倾翻。** 扶手（x = 0.69 m）在底座前端（0.66 m）之外，100 kg 的人整个挂在扶手上时，压力中心离底座前端只剩 7 cm；侧推约 0.34 倍体重就会翻。底座前端建议伸到 ≥ 0.75 m；台架与床固定后风险更小。
- **体重和肌力不随身高缩放。** 1.75 m 用户费力偏高，部分来自这一点；已写入局限。
- **皮肤剪切。** 前滑的净值很小，但支撑全程皮肤累计受到的剪切位移中位数约 10 cm，最大 13.5 cm；建议坐垫表层用可滑动的面套。

## 方法与局限
- 输入：
  - 课程背景（含老师 10/26 要点）、设计总结、网页源码、8 个计算脚本、`model.py` 节选、结果 JSON 摘要；
  - 16 张截图：各节截图，机构在起身 0 / 35 / 70% 时的画面，以及三视图。
  - 每个角度约 13 万输入 token。
- 复核脚本（`audit/checks/`，在 `model/calc_v13` 目录下运行）：
  - `own_checks.py`：夹点间隙、抗倾翻；
  - `verify.py`：横管与摇杆 A、偏心推力和铰点受力、放手时前倾、前滑最大反弹、支撑段费力、推杆速度比、竖直方案公平对比。
  - `verify.json` 是 `verify.py` 的输出。
- Gemini 关于摩擦系数、推杆速度、组织压迫的数字属于常识量级，没有查证文献；结论只用了方向性判断。
